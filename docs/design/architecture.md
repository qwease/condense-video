# 架构设计 - Condense Video Python Backend

**设计日期**: 2026-02-27
**状态**: 设计完成，待实现

## 1. 概述

将现有的 Node.js + Python 混合 skill 转变为高效的 Python 后端服务，采用 Web API + 异步任务队列的混合模式。

### 1.1 核心目标

- **Web API 服务**: 快速响应 HTTP 请求，提供 RESTful API 和 WebSocket
- **异步任务处理**: Celery + Redis 处理耗时的视频处理任务
- **容器化部署**: Docker Compose 一键启动，支持水平扩展
- **全配置化管理**: 所有配置通过 `.env` 文件管理，无需修改代码

## 2. 整体架构

```
┌─────────────────────────────────────────────────────────────────────┐
│                        客户端层                                       │
│  Web 前端 / CLI 工具 / 移动应用  ←→  FastAPI (REST API)             │
└─────────────────────────────────────────────────────────────────────┘
                                 ↓
┌─────────────────────────────────────────────────────────────────────┐
│                        API 网关层                                     │
│  FastAPI (uvicorn)                                                   │
│  - POST /api/v1/videos/process  (提交视频处理任务)                    │
│  - GET  /api/v1/tasks/{task_id}   (查询任务状态)                      │
│  - GET  /api/v1/videos/{id}       (获取处理结果)                      │
│  - WebSocket /ws/tasks/{task_id} (实时进度推送)                       │
└─────────────────────────────────────────────────────────────────────┘
                                 ↓
┌─────────────────────────────────────────────────────────────────────┐
│                        消息队列层                                     │
│  Redis (Celery broker + 结果存储 + 任务状态)                          │
│  - 任务队列: celery-task-queue                                        │
│  - 进度频道: task-progress:{task_id}                                  │
│  - 结果存储: task-result:{task_id}                                    │
└─────────────────────────────────────────────────────────────────────┘
                                 ↓
┌─────────────────────────────────────────────────────────────────────┐
│                        任务处理层                                     │
│  Celery Workers (可水平扩展)                                          │
│                                                                      │
│  工作流 Pipeline (任务链):                                            │
│  1. video_download      - 下载/接收视频文件                           │
│  2. audio_extract       - 提取音频 (ffmpeg)                           │
│  3. [并行] asr_transcribe + ppt_extract                             │
│  4. [并行] ppt_ocr                                                    │
│  5. content_classify    - 内容分类 (LLM 融合语音+PPT)                 │
│  6. chapter_segment     - 章节切分                                   │
│  7. content_summarize   - 内容总结                                   │
│  8. tts_generate        - TTS 生成                                   │
│  9. video_edit          - 视频剪辑合成 (ffmpeg)                       │
│  10. cleanup            - 清理临时文件                                │
└─────────────────────────────────────────────────────────────────────┘
                                 ↓
┌─────────────────────────────────────────────────────────────────────┐
│                        存储层                                         │
│  - MinIO/S3: 视频文件存储                                             │
│  - Redis: 任务状态、进度、缓存                                         │
│  - 文件系统: 临时处理文件                                             │
└─────────────────────────────────────────────────────────────────────┘
```

## 3. 核心设计理念

| 理念 | 说明 |
|------|------|
| API 与 Worker 分离 | API 快速响应请求，Worker 异步处理耗时任务 |
| 任务链模式 | Celery chain 串联各步骤，支持断点续传 |
| 并行优化 | ASR 转录与 PPT OCR 并行执行，提升处理速度 |
| 进度推送 | WebSocket + Redis Pub/Sub 实时反馈处理进度 |
| 容器化部署 | Docker Compose 一键启动，易于扩展 |

## 4. 技术栈

| 组件 | 技术选择 | 说明 |
|------|----------|------|
| Web 框架 | FastAPI | 现代异步框架，自动 OpenAPI 文档 |
| 任务队列 | Celery + Redis | 成熟的异步任务队列，支持任务链 |
| 数据库 | Redis | 任务状态、进度、结果存储 |
| 对象存储 | MinIO/S3/本地 | 可配置的存储后端 |
| 容器化 | Docker + Compose | 容器化部署 |
| ASR/OCR/LLM | DashScope API | 阿里云服务 |
| 视频处理 | FFmpeg | 音视频处理 |

## 5. 优化点：并行工作流

原 JS 设计为串行处理，新设计支持并行：

```
原设计:
audio → asr → ppt → ocr → classify → ...

新设计:
       ┌→ audio → asr ─┐
video ─┤               ├→ classify → ...
       └→ ppt → ocr ──┘
```

**并行优势**:
- ASR 和 OCR 是独立步骤，可同时进行
- 减少总体处理时间约 30-40%
